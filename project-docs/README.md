# 전략실컷빌더 (Strategy Cut Builder)

> **담당 영역: 엔드투엔드 플로우의 "컨텐츠 빌더" — 마케팅컷 생성 에이전트**
> 앞단(디자인 빌더)에서 브랜드 DNA + 제품 디자인을 받아, 마케팅용 캠페인/인플 이미지를 생성하고, 뒷단(마케팅 캠페인 빌더)에 전달한다.

## 프로젝트 히스토리 & 배경

1. **기점**: 세르지오 타키니 기획 디자인 팀에서 **디자인 에이전트**를 만들어 회장님께 보고 → 반응 좋음
2. **확산**: AX팀(우리)과 AI전략실이 각각 비슷한 프로젝트를 준비하고 있었음 → 다음주 보고에 합치기로
3. **목표**: 개별 에이전트들은 있지만 **서로 연결되는 구조가 아님** → 이참에 연결해서 제대로 된 E2E 에이전트 구축
4. **현실 문제**: 기획팀 DNA 방향성과 이미지 생성 전략을 결합하여 정량화 필요 → 예린(AX팀)이 **이미지 생성에 최적화된 DNA 가드레일을 구축하되**, 나중에 트렌드 에이전트가 연결돼도 퀄리티 유지되도록 설계
5. **전략**: 트렌드 에이전트가 안 되면 → **추구미 이미지로 억지로라도 좋은 이미지 생성** → 트렌드 데이터와 사후 엮어서 보고

### 역할 분담

| 역할 | 담당 | 에이전트 | 저장소 |
|------|------|---------|--------|
| 디자인 에이전트 | 세타 기획 디자인 팀 | 트렌드→제품 디자인 시뮬 | 별도 GitHub |
| 트렌드 에이전트 | 다른 담당자 | 경쟁사/트렌드 수집·분석 | 별도 GitHub |
| **마케팅컷 에이전트** | **예린 (AX팀)** | **DNA+추구미→캠페인/인플컷** | **이 저장소** |
| **총괄 PM** | **김효은** | 각 에이전트 GitHub clone → 연결 | PM의 Claude Code |

### 연결 구조

```
[각 담당자의 GitHub]
├── 디자인 에이전트 repo (세타팀)
├── 트렌드 에이전트 repo (다른 담당)
├── 마케팅컷 에이전트 repo (예린 — 이 저장소) ← 여기
└── (기타 에이전트들)
         │
         ▼
[PM 김효은의 Claude Code]
  각 repo를 clone → 자기 환경에서 전체 파이프라인 연결
  PM의 Claude Code가 각 에이전트의 SKILL.md를 읽고 순서대로 실행
```

**따라서 이 저장소의 README/SKILL.md는 PM의 Claude Code가 읽었을 때 바로 이해하고 실행할 수 있어야 한다.**

### 이중 전략 (Plan A / Plan B)

```
Plan A: 트렌드 에이전트가 제대로 연결되면
  트렌드 데이터(경쟁사 분석, 시장 규모) → brand-dna.json에 반영 → 이미지 생성

Plan B: 트렌드 에이전트가 없거나 미흡하면 (추구미 역설계)
  추구미 이미지(라이프스타일 비전) 먼저 확보
  → VLM 분석 → DNA 역추출 → 이미지 생성
  → 트렌드 데이터는 사후에 "근거"로 엮기
```

**핵심: 결과물(이미지)이 좋으면 앞단 논리는 나중에 채워도 된다. 이미지 퀄리티가 최우선.**

## 전체 파이프라인에서의 위치

```
엔드투엔드 플로우:
트렌드 분석 → 시장 규모 → 브랜드 포지셔닝 → 상품 기획 → 시각화 시뮬레이션 → 컨텐츠 방향 → 캠페인 시나리오 → 리테일 환경

[디자인 빌더]                    [컨텐츠 빌더 ← 우리]              [마케팅 캠페인 빌더]        [리테일 빌더]
 경쟁사 크롤링                    마케팅컷 생성 에이전트              IMC 설계                   매장 VP
 제품 이미지 Matrix               캠페인컷 + 인플컷                 채널 배너                  제품 연출
 브랜드 DNA 확정                  라이프스타일별 톤앤무드             셀럽/인플루언서 전략         VMD 시뮬
         │                              │                              │                        │
         └──── brand-dna.json ──→ 우리가 받음          우리가 전달 ──→ 이미지+프롬프트 ──→ 다음 빌더가 받음
              (하네스)                                                  (결과물)
```

## 앞단 인터페이스 (디자인 빌더 → 우리에게 들어오는 것)

| 인풋 | 형식 | 누가 만드는가 | 경로 |
|------|------|-------------|------|
| **브랜드 DNA** | JSON | 디자인 빌더 (또는 우리가 크롤링+분석) | `brand-dna/{brand}.json` |
| **시즌/카테고리** | 텍스트 | 사용자(전략실) | "27SS WJ" 등 |
| **추구미 레퍼런스** | 이미지 폴더 (7~15장) | 사용자(전략실) | `Downloads/{brand}추구미/` |
| **제품 이미지** | 이미지 폴더 | 디자인 빌더 (제품 Matrix 확정 후) | `db/strategy-cut-builder/{brand}/` |
| **경쟁사 트렌드** | 이미지 폴더 | 디자인 빌더 (크롤링) | `db/strategy-cut-builder/trend-images/` |

**DNA가 없으면?** → 우리 파이프라인이 자체 생성 (크롤링 → VLM 분석 → JSON 자동 생성)
**추구미가 없으면?** → 사용자에게 요청 (이건 사람의 판단 영역)

## 뒷단 인터페이스 (우리 → 마케팅 캠페인 빌더에 전달하는 것)

| 아웃풋 | 형식 | 용도 | 경로 |
|--------|------|------|------|
| **캠페인컷 이미지** | PNG (3:4) | IMC 설계, 매거진, 배너 소스 | `Fnf_studio_outputs/strategy-cut-builder/{brand}/` |
| **인플컷 이미지** | PNG (3:4) | SNS 컨텐츠, 인플루언서 가이드 | 같은 폴더 |
| **프롬프트 텍스트** | TXT | 재생성/튜닝 시 재사용 | `{scene_id}_prompt.txt` |
| **DNA 가드레일** | JSON | 다음 빌더의 품질 기준 | `brand-dna/{brand}.json` |
| **모델 비교** | Gemini/GPT/Higgsfield 3종 | 베스트 셀렉용 | 같은 폴더에 `_gemini`/`_gpt`/`_hf` 접미사 |

**다음 빌더가 쓰는 방법:**
- 마케팅 캠페인 빌더 → 우리 이미지로 컨텐츠 기획안(PPTX) 생성, 채널 배너 제작
- 리테일 빌더 → 우리 이미지로 매장 연출컷/VMD 시뮬레이션
- SNS Grid → 우리 이미지를 피드에 직접 등록

## 우리의 핵심 책임: 이미지 퀄리티 디벨롭

> **이 에이전트의 존재 이유는 "진짜 화보 같은 AI 이미지"를 만드는 것.**
> 코드/파이프라인은 수단이고, 결과물 이미지의 퀄리티가 전부다.

### 현재 퀄리티 레벨 (2026-04-30 기준)

| 항목 | 상태 | 다음 목표 |
|------|------|----------|
| **화보 감도** | O — Hasselblad+Portra 프롬프트로 에디토리얼 수준 달성 | 브랜드별 세부 톤 차이 |
| **모델 퀄리티** | O — K-pop/editorial 키워드로 아줌마→모델 해결 | 브랜드별 모델 페르소나 고정 |
| **배경 자연스러움** | △ — 가끔 AI 느낌 배경 나옴 | VLM 검수로 자동 리젝 |
| **소재감/광택감** | △ — 듀베티카 OK, MLB/DX 미흡 | 브랜드별 소재 키워드 튜닝 |
| **포즈/표정** | △ — 때때로 부자연스러움 | JSON 스키마 강제 분석 적용 |
| **AI 냄새 제거** | O — "순간 포착" + 필름 스펙 + 불완전함 기법 | 지속 모니터링 |

### 퀄리티 디벨롭 로드맵

```
[Phase 1] 기본 파이프라인 구축 ✅ (2026-04-30 완료)
  - DNA 자동 추출/블렌딩
  - 프롬프트 온리 생성 (anti-AI 기법)
  - Gemini + GPT + Higgsfield 3모델 병렬

[Phase 2] 브랜드별 퀄리티 튜닝 (진행 중)
  - 브랜드별 추구미 VLM 정밀 분석 → 프롬프트 개선
  - DNA 분석을 JSON 스키마 강제로 프리셋 수준 보장
  - 모델별 최적 프롬프트 분기 (Gemini용/GPT용/Higgsfield용)

[Phase 3] 검수 자동화 + 피드백 루프
  - VLM 7-Gate 검수 → 자동 리젝 → 프롬프트 조정 → 재생성
  - 생성 결과 A/B 비교 데이터 축적
  - 어떤 프롬프트 키워드가 어떤 모델에서 효과적인지 학습

[Phase 4] 스타일 일관성 + 대량 생성
  - 같은 브랜드의 컷들이 동일한 세계관/톤으로 통일
  - 한 번에 50~100장 생성 → 자동 셀렉 → 상위 N장 전달
  - 시즌 간 DNA 변화 추적 (26SS → 27SS → 27FW)
```

### 검증된 핵심 프롬프트 전략 (prompt-strategy.md 참조)

1. **DNA 분석은 항상 JSON 스키마 기반** — 자유형 분석 금지, `dna_schema.py` 스키마 강제
2. **브랜드별 모델 키워드 고정** — 듀베(editorial model) / MLB(K-pop 걸그룹) / DX(fitness influencer)
3. **3모델 병렬 생성** — Gemini + GPT + Higgsfield, 베스트 셀렉
4. **"~하는 순간을 포착"** — 포즈 아닌 행동 중간 묘사 = 자연스러움
5. **필름 카메라 스펙** — Hasselblad 500CM, Kodak Portra 400 = 화보 깊이감
6. **자연스러운 불완전함** — 바람에 날리는 머리카락, 비대칭 포즈, 피부 텍스처

## 스킬/에이전트 구조

```
에이전트: strategy-cut-agent.md (파이프라인 오케스트레이터)
│
├── /전략컷크롤링       ← 앞단에서 DNA 없을 때 자체 생성
├── /전략컷DNA분석      ← 앞단에서 DNA 없을 때 자체 생성
├── /전략컷프롬프트      ← 핵심: 추구미 VLM 분석 + DNA 블렌딩
├── /전략컷생성         ← 핵심: 3모델 병렬 프롬프트 온리 생성
└── /전략컷검수         ← DNA 가드레일 대비 7-Gate 검수

뒷단 연계 스킬 (이미 FNF Studio에 있음):
├── /컨텐츠기획안       → 캠페인컷으로 30슬라이드 PPTX
├── /채널배너          → 캠페인컷으로 인스타/페북/네이버 배너
├── /제품연출          → 매장 VP/VMD 컷
└── SNS Grid          → 인플컷 → 피드 자동 등록
```

## 새 브랜드 추가 방법

1. `brand-dna/{brand}.json` 생성 (필수 필드: brand, season, positioning, mood, color, setting, styling, model, fabric, data_driven_guardrails)
2. 추구미 이미지 폴더 준비 (7~15장 — 이 브랜드의 "이런 느낌" 레퍼런스)
3. `/전략컷크롤링 {brand}` 실행 (자사몰+인스타 이미지 수집)
4. 파이프라인 자동 실행 → 캠페인+인플 컷 생성
